# 路线图

## v0.1：离线批处理可执行闭环

本轮代码范围：

- 本地声音导入、原音保留、固定参考、F0/信号统计。
- 用户手动声线描述、候选试听与保存；明确区分默认值和测量结果。
- VoxCPM2 设计与 TTS、Seed-VC v2 纯音色 VC 的真实上游适配。
- CLI、API、中文 Web UI，共用服务逻辑。
- 任务持久化、日志、失败原因、取消与结果文件。
- 各后端独立环境、固定源码/权重 revision、显式模型下载。
- 同名文字数据准备、可选本地 ASR、按源文件划分、LoRA 配置和官方训练启动。
- 项目方案、Windows 路径、许可证与简明素材来源记录。

交付检查分开进行：CPU 测试验证文件、接口和任务行为；真实模型推理验证输出是否可用；听感测试判断是否符合目标声音。前一种通过不能替代后两种。目前没有用户音源或大权重，所以没有宣称已经训练了角色模型。

## 第一轮实机验收

1. 用一段干净、明确单人的参考建立声音档案。
2. 用固定的中性、疑问、长句、数字、专有名词文本生成 TTS。
3. 用至少两个不同源说话人读同一组短句，转换为同一目标音色。
4. 听内容是否错漏、音色是否一致、源音色是否残留、句尾是否自然、呼吸/情绪是否受损。
5. 记录模型 revision、参数、种子、耗时、输出时长和峰值显存；测得之后再讨论设备上的速度预算。
6. 在同样的试听组下比较微调前后结果，防止用训练文本听感代替泛化判断。

对齐、清晰度与音色应分别判断。ASR 错字率、说话人向量余弦相似度和 F0 统计可辅助分析，但都不能单独代表“这个声音是否像同一个人”。

## v0.2：稳定性与工作流

- 常驻后端和有边界的显存管理，减少每条任务冷启动。
- 按参考内容和模型版本保存神经 prompt cache；支持迁移检查与失效重建。
- 多参考音频 bank、参考质量比较和说话人一致性检测。
- 长文本自然段切分、段落重试、停顿编辑、合成结果拼接与响度控制。
- 本地队列批量导入、播放对照与听评记录。
- 实际需求明确后接入 OpenVoice V2 或旧 RVC 模型，保留标准身份资产。
- 在独立测试后开放 LoRA 切换与新底模版本迁移。

这些项目不是 v0.1 已实现功能；优先级由真实首轮音源暴露的问题决定。

## v0.3：需要数据支撑的控制能力

- 用人工标注和客观指标校准语义控制，而不是把任意音色形容词映射成看似精确的数值。
- 明确区分音色身份、表演方式、F0 轨迹、口音和录音条件。
- 若要唱歌，接入独立 F0 条件链路并检验旋律与节奏。
- 若要实时变声，重新制定算法缓冲、音频设备回环、参考缓存和延迟测试；不能把离线分块输出叫作实时麦克风变声。

## 研究方向：形成自己的模型

先积累可比较的数据、参考和评价结果，再决定是否做蒸馏、多任务微调或共享表示研究。不能直接平均 VoxCPM2、Seed-VC、RVC 的权重：模型架构、token/latent 定义和解码器不同。

真正的新模型需要明确训练目标与数据预算；“统一软件接口”已经能形成新的可用产品，但不应被宣传成已经训练了新的基础模型。
