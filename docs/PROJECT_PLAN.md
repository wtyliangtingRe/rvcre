# RVCre 项目方案

本项目把“创造、保存并重复使用一个声音”作为主线。用户可以导入参考音频，查看可测量的音高与信号统计；也可以手动描述声线，生成多个候选，试听后保存。保存后的同一个声音档案同时用于文本合成和音频变声。

第一版采用 **VoxCPM2 负责声音设计与 TTS，Seed-VC v2 负责纯音色 VC**。项目整合代码采用 GPL-3.0-only。主要工作是可靠的数据流、声音档案、任务管理和上游适配；不从零预训练声学基础模型，也不把不同架构的模型权重强行混合。

## 1. 用户流程

1. **导入声音**：读取本地单人录音，保留原文件；生成最多 12 秒的固定 `reference.wav`，记录截取区间、来源备注和原音 SHA-256。
2. **观察与描述**：展示这段参考的 F0 中位数、P10/P90、响度与静音等统计。用户自己指定偏低/偏高、轻盈/饱满、明亮、气声、沙哑等设计意图。
3. **设计候选**：VoxCPM2 根据描述生成 1–6 个候选。用户试听、保存满意的候选，形成新的声音档案和可追溯版本关系。
4. **TTS**：输入文字，用已保存的参考音频生成目标声音；可控模式接受表达提示，Hi-Fi 模式使用与参考音频严格对应的转写。
5. **VC**：输入用户实际表演/朗读的源音频，用同一档案的参考音频替换声音身份。首版默认保留源表演意图，不打开口音和情绪转换路径。
6. **需要更稳定时再微调**：先把本地音源整理为有转写的训练/验证集，再调用官方 VoxCPM2 LoRA 训练器。没有必要为每个初次试听的声音先训练模型。

## 2. 模型职责

| 部件 | 选择 | 用途与边界 |
|---|---|---|
| 声音设计、参考驱动 TTS | VoxCPM2 | 文本与声线提示生成音频；声音设计的语义控制有随机性，先试听再固定参考 |
| 音频到音频转换 | Seed-VC v2 | `convert_style=false`、`anonymization_only=false`；不把 VC 改写成 ASR → TTS |
| 测量 | SoundFile、SciPy、librosa pYIN | 时长、信号质量、可用有声帧的 F0 统计；不自动判断年龄、性别或全部音色语义 |
| 可选数据转写 | 本地 faster-whisper | 生成待复核转写和时间戳；运行时不自动下载 ASR 模型 |
| 说话人适配 | 官方 VoxCPM2 LoRA | 用预训练权重微调；保留基础模型与 LoRA 的对应关系 |
| 后续兼容路线 | OpenVoice V2 / 已有 RVC 模型 | OpenVoice 可作为 MIT 备选；RVC 可复用已有音色资产，但均不是 v0.1 已接入的后端 |

VoxCPM2 与 Seed-VC v2 的输出采样率不同，不应把升采样解释成质量提升。比较输出时应统一试听响度，保留原始输出文件。

## 3. 声音身份如何稳定

真正持久化的是**参考音频和档案**，不是“写了同一句提示词”。每次重新设计都可能产生不同的声音。选定候选之后，后续合成与转换应复用已保存的参考，而不是重新抽样设计。

两个模型内部的 speaker embedding 不能互换。v0.1 不实现跨进程神经提示缓存；每个任务可以在自己的后端中重新提取条件。未来缓存必须同时绑定参考音频内容、模型版本和提取器版本，不能仅用显示名称作为缓存键。

共同参考也不是数学上的“同一人保证”：TTS 和 VC 会产生不同程度的音色偏差。产品需要用固定文本和不同源说话人的表演做一致性测试，再决定参考是否合格。音高分布只是评估的一部分，不能把 F0 相同当成身份相同。

## 4. 第一版交付边界

第一版是本地批处理工作台，提供 CLI、HTTP API 和中文 Web UI、声音档案、任务日志、可取消任务、数据准备与 LoRA 启动包装器。长篇文字按段提交；一次 TTS 最多 600 字符，声音设计试听文本最多 240 字符。

以下能力没有被伪装成已实现：实时麦克风变声、任意声音的完全自动语义反演、精确独立的物理音色滑杆、严格逐帧的音高保持、跨后端共享神经向量、从文本直接生成完整唱歌表演、自动选择“最像”的候选、自动蒸馏一个新的基础模型。

当前仓库不包含用户音源、预训练大权重或训练结果。开发与 CPU 测试可以完成接口、格式和流程验证；真实合成品质、显存与速度需要在有模型和音源的环境中测量。详见 [验证记录](VALIDATION.md)。

## 5. 为什么这样组合

直接使用原生参考 TTS 可以少一次音频重建。VC 则承担“我先把这句话演好，再换成目标声音”的任务。这样既保留文本输入的方便，也保留源录音里的停顿、节奏和表演信息。VC 仍是生成式重建，不能承诺所有细节无损。

如果某种 TTS 输出确实需要再次稳定音色，可以以后增加可选的 TTS → VC 链路，并用盲听确认收益。首版不强制所有合成音频再经过一次变声。

Seed-VC v2 的纯音色路径不使用 AR 风格转换；但它没有显式 F0 条件接口，也不保证音高绝对不变。唱歌与精确旋律控制应另接合适的 F0 条件模型。项目上游已归档，我们固定版本并在适配层承担维护，不把它描述成持续活跃更新的上游。

## 6. 后续数据与训练

用户已有的音源先按说话人分开，同名 `.txt` / 纯文本 `.lab` 必须与录音内容一致。一次长录音的全部切片只能进入同一个数据划分。训练与验证参考都来自相同说话人、相同划分，不能把验证素材偷偷用作训练参考。

优先用少量干净参考测试零样本路线；当稳定声音身份确实需要更强约束时，再收集更多同一声音的有效片段并做 LoRA。具体工具、目录、可执行命令见 [数据准备与训练](DATASET_TRAINING.md)。素材来源记录是普通项目元数据，不是阻止本地开发的审批机制。
